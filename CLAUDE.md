# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Keeps a supporter's calendar in step with the London Lions men's fixtures and writes a matchday programme on the morning of each game. Read `GLOSSARY.md` before naming anything: it fixes the terms (Fixture, Competition, Feed, Home fixture, Headline, Season opener) and lists words to avoid.

## Commands

Node 22, plain ES modules, no build step, no TypeScript (ADR 0004). No linter is configured.

```sh
npm ci
npm test                                        # node --test, everything in test/
node --test test/reconcile.test.js              # one file
node --test --test-name-pattern="Genius"        # tests whose name matches (don't pass a directory)
npm run sync -- --dry-run                       # fetch sources, print the change notice, write nothing but out/notice.json
npm run sync -- --from <dir> --dry-run          # same, reading saved source pages from <dir> instead of the web
npm run programme -- <data.json> <programme.md> <out-dir>   # render index.html + A5 programme.pdf
node src/programme/check.js <data.json> <programme.md>      # validate a programme without rendering the PDF
npm run season                                  # regenerate the season index (index.html)
```

Try a render with the worked example: `npm run programme -- test/fixtures/programme/bristol.json test/fixtures/programme/bristol.md out/bristol`. The PDF step needs a local Chrome for `playwright-core`.

Tests read saved source pages from `test/fixtures/`. When a source's markup changes, save a fresh copy there rather than hitting the network in a test.

## Architecture

Two scheduled GitHub Actions workflows do all the work and commit their output to `main` as `github-actions[bot]`. GitHub Pages serves the repo root, so the repo is both the site and the season archive (ADR 0002). Each workflow is scheduled at two UTC hours and a guard step exits unless it is the intended Europe/London hour. Both share the `generated-output` concurrency group.

### Fixture sync (`src/sync/`, 07:00 UK)

`run.js` reads each competition in `config/competitions.json` from its source (`sources/genius.js` for SLB competitions, `sources/euroleague.js` for EuroCup), then `reconcile.js` merges the rows into `data/fixtures.json`. `crosscheck.js` compares the result against the club schedule page (`sources/club.js`), which has no ids and only raises warnings. Output: `data/fixtures.json`, the three ICS feeds in `feeds/`, the season index, and a change-notice email.

- Every fixture gets an internal id on first sight, and that id is its ICS UID for life. Source ids are attributes used for matching (ADR 0001). Never derive a UID from a source id.
- A source that fails is recorded in `state.sources` and its fixtures freeze until it recovers.
- `config/overrides.json` patches fixtures by id; `venues.json` and `opponents.json` are hand-kept lookup tables.

### Programme run (`src/programme/`, 08:00 UK on game days)

1. `today.js` picks today's fixture.
2. `gather.js` fetches every source (league pages via `league.js` and `previous.js`, news via `news.js` and `google-news.js`), applies freshness windows, computes every number, and writes `data.json` plus `bundle.json`.
3. Claude, via `claude-code-action` with no web tools, follows `src/programme/prompt.md` to write `programme.md` from the bundle alone, and loops on `check.js` until it passes (ADR 0003).
4. `build.js` renders through `render.js` (HTML) and `pdf.js` (Playwright), into `programmes/<UK date>-<opponent>/`.
5. `email.js` sends the programme, or a "no programme today" email naming the failed step.

The split matters: numbers and structured blocks come only from `data.json`, and prose comes only from the bundle. Every paragraph carries a `[src:<id>]` marker, and the renderer rejects missing or unresolved markers, unknown or out-of-order sections, and player cards naming someone off the roster. `docs/programme-content.md` is the full content model and the rules the renderer enforces. Update it, `prompt.md` and the Bristol fixture together when the content model changes.

### Site (repo root)

`index.html` is generated by `src/app/season.js`; don't hand-edit it. `sw.js` serves today's programme network-first and past ones from cache. It reads the date out of the path built by `programmePath()`, so changing that path format breaks offline caching. `install/` is the installable web app entry point. `assets/fonts/` are self-hosted.
